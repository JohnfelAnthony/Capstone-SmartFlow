# SmartFlow Road Editor — early implementation

The Road Editor is a local, offline companion for authoring provisional native networks. Double-click **Start Road Editor.cmd**, or run `.venv\Scripts\python.exe -m tools.road_editor`. The browser opens on a random loopback port; `--no-browser`, `--port` and `--data-dir` are available for testing. The editor uses the existing SmartFlow Python environment and adds no packages. For a startup error, run the command in a terminal to see its message.

Open a registered network or import a JSON copy. Select and drag nodes or intermediate vertices, change widths, lane counts, speed and direction, insert a midpoint or remove an intermediate vertex, draw a road through multiple points, or draw an island. To add a road, choose **Add road**, click its starting point and bends, then click an existing node, double-click the final point, or choose **Finish road**. Escape cancels the in-progress shape. Choose **Split road** and click a point on a road, or use the inspector to split the longest segment at its midpoint. Choose **Connect crossing roads** and select two roads to explicitly join one unambiguous crossing; a visual crossing alone creates no connection. The source-side road keeps its ID, each new road gets a new ID, affected turn restrictions are remapped, and the new junction defaults to no signal. Deleting a node lists the connected roads and affected restrictions before confirmation; the Site B study junction cannot be deleted. Any newly possible turns are provisional and need legal review. Native validation may still reject short split segments. A road added at an existing boundary converts that node to a provisional no-signal junction. Use Undo if the result was unintended. Save projects separately from installed networks. A separate recovery draft is offered on restart after an unsaved change; saved projects use revision checks so a second window cannot silently overwrite them. Download is explicitly an **unvalidated draft**, never an installed revision. Existing networks, scenarios and recordings are not changed.

Select a junction to review its direction-compatible turn movements and allow or prohibit each one in the draft. The list follows native one-way and no-U-turn rules; it does not determine which turns are legal on site. Changes are undoable and update the native preview after validation.

The grey pavement preview comes from the native parser. It disappears while the draft is changing and returns after a successful structural check. The editor flags self-crossing islands, islands touching native road-lane pavement, possible conflicts with a conservative envelope around a connector, and boundary entrances or exits that cannot reach another boundary under the saved turn restrictions. A connector-envelope warning can be a false positive; inspect it rather than treating it as a proven collision. Select “Show island” or “Show boundary” on an issue to inspect it. These checks do **not** establish full connector or swept-vehicle clearance, traffic safety, legal-turn review, field calibration or independent validation. There is deliberately no install button or activation-ready export yet. Do not replace a registered network manually with an editor draft. Site B's frontage reconstruction is not automatically completed by this tool.

Import a local PNG or JPEG (up to 20 MB and 40 million pixels) as a project reference. Hide **Native lanes** to see it under the editable centerlines. Set the anchor coordinates, rotation and opacity in the reference controls. To set its scale, choose **Select two scale points**, click two image features, enter their separation in metres and apply it. The first point stays fixed as the image is rescaled. Mark a distance as measured on site only when that is true; otherwise the scale remains a visual estimate. Show/hide and alignment lock are available. The image and its transform are stored in the editor project and recovery copy, not the downloaded native-network JSON. Reference-image changes participate in Undo/Redo alongside road edits.

On save and recovery the local server reads the encoded image header to enforce the pixel limit independently of the dimensions supplied by the browser. This is a header and size check, not a complete image-decoding or integrity check; the browser decodes the image during normal import.

Lane count and carriageway width are separate. Changing the lane count or one-way setting retains the previous per-direction width; use **Set width to lanes × 3.3 m** only when that approximation is intended. Ambiguous imported lane tags are shown with a warning, and the original tag is retained in the road's editor provenance when changed. Widths and lane counts still need site verification.

Draft validation flags road shapes that cross, touch or retrace themselves; **Show road** selects the affected shape for correction. It also relies on the native parser to reject duplicate IDs. These checks do not establish full vehicle clearance or make a draft eligible for installation.

Validation identifies disconnected components, lanes with no permitted exit, missing Site A/B study junctions and boundaries that cannot reach or be reached from the applicable study junction. These are routing diagnostics, not proof that the proposed movements are legal or physically safe.

Possible overlaps between lane-width envelopes outside connectors appear as warnings with controls to focus both roads. The check uses conservative rounded segment endpoints and can flag lanes that do not actually conflict, including opposing lanes on a curved road. Conversely, it does not check all vehicle bodies, connectors or traffic dynamics. Treat each warning as a review prompt, not a collision result.

Island diagnostics also use conservative vehicle-body envelopes around lane and permitted-connector paths, including lane ends and each supported class. They flag islands that overlap or touch one another for review; contact can be intentional, such as a planted strip meeting a paved nose. The circular envelopes may flag geometry that a particular vehicle would clear. **Review connector samples** and **Review lane samples** run separate, potentially slow sampled-body diagnostics on a structurally valid draft; they identify the class and island, and clear results after edits. Connector results distinguish sampled actual-body contact from the expanded envelope. The lane check aligns bodies to the lane heading and does not include extra dynamic yaw. Both sample selected lateral positions only, do not cover all paths or interactions and cannot certify clearance or permit installation.

Enable **Native directions / turns** to see arrows for native lane travel and dashed lines for the turn connectors permitted by the draft's restrictions. The overlay is generated from the native preview; it disappears while a changed draft is being checked. Visible movements are model settings, not confirmation of legal turns.

Select an island to label it, mark it planted or paved, add a corner at its longest edge, remove corners, or drag them. A polygon must retain at least three corners. Explicitly closed rings remain closed during these edits. Planted state uses the same `planted` field as SmartFlow's 2D renderer; it does not make an island a physical vehicle obstacle.

**Download review bundle** prepares a JSON document containing the exact draft, its hash, current validation issues and an SVG overview. **Download overview SVG** prepares the same centreline-and-island view as a separate image. Both are explicitly labelled unvalidated and are not installable; the SVG is a schematic, not a vehicle-clearance plot. In the development environment, browser file downloads were canceled even for an unrelated control file, so the generated content was inspected in the browser but successful saving to disk still needs a normal desktop-browser check.

This is an initial slice of the plan, not a finished implementation. In particular, remaining topology operations, comprehensive physical clearance, validated review exports, and the authenticated revision-installation workflow remain to be built. Splitting, connecting a single unambiguous crossing and editing draft turn restrictions are available as described above. Project drafts may be invalid and can still be saved. The current undo stack lives in the browser; reopening a project starts a new history.

The pavement preview is drawn like SmartFlow's 2D map (sidewalks, kerbs, asphalt, lane dividers, yellow centre lines, stop lines and crosswalks) by `scene.js`, a display-only port of `src/simulation/scene-geometry.ts` that reads the native preview; it adds no physics and is covered by `node --test tools/road_editor/scene.test.mjs`. The editable centre lines and nodes are the dashed teal layer on top. Buildings, trees and vehicles are not drawn.

Site features (buildings, sheds, service lanes, junction pavement and other drawn-only context) are shown as read and kept unchanged on save, and the editor has no controls for them. `data/networks/tagum_site_b.json` is generated by `tools/site_b_measured_layout.py`, so an edit saved over it no longer matches that generator, and `tests/test_site_b_measured_layout.py` will report the difference.

## Verification on November 2, 2026

The focused editor, island, Site B corridor, site network and scenario suites passed **24 tests**. They cover native preview/fingerprint round trips, invalid drafts, revision conflicts, recovery storage, loopback token/origin rejection and refusal of activation-ready export. `node --check tools/road_editor/app.js` passed. In an isolated browser and data directory, Site B opened, a two-way road width change updated the total width, an unsaved draft was recovered after reload, and a project was saved and reopened. These checks did not cover all editing actions, complete browser acceptance, long-run simulation safety, or installation into SmartFlow.
